# Tango 终端极致性能设计

日期：2026-11-15
状态：已批准（2026-11-15，用户选择 A→B，并确认 5 项架构决策）
范围：`ui/terminal`、`ui/terminal/vt`、必要的 `ui` 输入接线；不包含编辑器性能和其他保留区改动。

## 1. 意图

把 Tango 终端从“功能完成、性能可用”提升到高吞吐、低延迟、稳定 60fps 的终端视图：输入尽量一帧内回显，大量 PTY 输出不阻塞 UI，滚动和重复绘制不重复做 CPU 工作，同时保持当前纯 Go、跨桌面和移动端、VT 行为兼容。

当前基线（Apple M4，macOS，低负载）:

- `BenchmarkTerminalCat`：395–401 MB/s（不含 UI）。
- 50 MB `cat`（PTY + VT + UI）：zsh -f 约 0.38–0.40s、约 58fps。
- `-auto` 按键到回显 p95：约 33ms；当前按键在 `paint` 中才发送，回显还要等下一帧。
- `ViewW.paint` 已有段缓存、脏行和 `ScrollShift`，但每帧仍遍历可见行并构造通用绘制指令；VT 读循环和 UI 读取共用锁。

## 2. 成功标准

在同一台机器、同一套回放数据、相同渲染器下比较优化前后；不以单次偶然最快值作为结论。

- 输入：p95 ≤ 16.7ms，p99 ≤ 25ms；不丢键、不改变键序、不破坏输入法组字。
- VT：以统一输入和统一 benchmark 生命周期测量纯 ASCII、彩色 ANSI、真实 PTY 三组；500 MB/s 是 A 阶段的优化目标和回归参考，不作为脱离输入类型的唯一硬门槛。三组都不得低于规格要求，且相对基线要有可重复提升；ASCII 解析不低于当前基线；所有现有 VT 测试和回放逐格一致。
- UI 输出：50 MB 可重复回放/PTY 场景保持 ≥ 60fps，p99 帧时间 ≤ 16.7ms；低负载下 zsh -f 的 50 MB 测量不劣于 0.5s。若硬件/系统调度使绝对值不可稳定复现，报告 CPU paint、锁等待、帧数和吞吐的分解数据。
- 滚动：10,000 行回滚滚动保持 ≥ 60fps，p99 ≤ 16.7ms；不可因缓存导致选区、光标、宽字符或滚动位置错误。
- 内存：默认 10,000 行、200 列、行缓存启用时，终端 Go 堆增量不超过当前基线的 1.5 倍；缓存有明确上限和淘汰策略。
- 性能优化不得引入新的第三方依赖、cgo 或平台专用终端模拟器；桌面三平台 `CGO_ENABLED=0` 编译/`go vet` 保持通过。

## 3. 不做的事

- 不在这一阶段实现 M2/M3 VT 功能（备用屏、鼠标协议、Kitty 键盘、同步输出、字形簇等），除非性能优化暴露出必须修复的兼容性问题。
- 不先做 GPU 专用终端纹理渲染；CPU renderer 仍是正确性基准，GPU 只消费现有绘制列表和损坏提示。
- 不以牺牲全屏程序、中文宽字符、组合字符、选区、剪贴板、IME 或移动端输入为代价换 benchmark 数字。
- 不把当前编辑器、设计基线或 Duplex iOS 保留区改动带入本分支。

## 4. 方案与选择

### 方案 A：事件直通 + 批量读写 + 可测量的绘制减负（第一阶段，采用）

保留现有 VT 屏幕数据结构和 `terminal.Conn` API，只改数据流：

1. **输入直通**：终端控件通过新增的实验性终端输入通道，在事件路由阶段立即编码并进入异步发送队列；不修改稳定的 `ui/input` 事件类型。`paint` 只负责收集/绘制，不再承担首次发送。必须保证事件顺序、IME composition 先提交再发 Enter、关闭时队列安全释放。
2. **读循环批量化**：读循环在锁外累积一批字节，在锁内一次写入，回复仍走独立额度；一帧内的多次输出只触发一次失效请求。记录 `feed` 等锁时间，避免凭感觉调大批次。
3. **绘制热点优化**：基于 CPU profile 优化 `paintRow`、`shapeSeg`、切片分配、`paint.List` 扫描和字形缓存；保留当前脏行/`ScrollShift` 正确性。段缓存容量继续按网格动态调整。
4. **基准设施**：加入稳定的输入延迟、PTY/VT 吞吐、输出帧时间、锁等待和分配 benchmark；所有优化都必须有前后数字和回放正确性测试。

优点：改动范围可控、先解决已知 33ms 延迟、兼容风险最低。缺点：如果通用 `paint.List` 和行遍历仍占主要成本，第一阶段无法达到最终上限。

### 方案 B：版本化屏幕快照 + 稳定行缓存（第二阶段，采用）

在 A 达到稳定基线后解耦 VT 写入和 UI 绘制：

1. VT/读线程维护可变屏幕；发布带全局版本、屏幕尺寸、视口偏移、光标和每行版本的快照。
2. UI 线程只读取快照，不持有 VT 主锁绘制；快照内的行数据使用受控的复制/共享策略，不能暴露 `CellAt` 内部指针。
3. 每行缓存以稳定行 ID、行版本、字体指标、配色版本和选区覆盖范围为键；未变化的行直接复用绘制 ops，变化行才重新切分、排版和提交。
4. 滚动优先复用行缓存和 `ScrollShift`；新增行、选区变化、光标变化、主题/字号/窗口变化会精确失效。缓存有容量上限，窗口缩放和主题切换可整批淘汰。
5. 建立并发测试：输出线程持续写入、UI 线程持续快照/绘制、窗口 resize、Cmd+K、回滚和选区复制并发运行，`-race` 通过。

优点：消除绘制期间的 VT 锁竞争，并把“未变化行不重做”落实到 CPU 指令层，是最接近性能上限的纯 Go 方案。缺点：需要重做快照生命周期、行 ID/回滚淘汰和选区映射，必须以回放逐格一致为门槛。

### 不采用：直接做 GPU 专用纹理终端

它可能有最高的理论吞吐，但会维护第二套 CPU/GPU 绘制逻辑，破坏当前 CPU/GPU 对照验收，并把平台差异提前引入；只有 A→B 后 profile 证明通用绘制仍是主要瓶颈，才另立 C 阶段设计。

## 5. 分阶段验收

### A 阶段

- 先写会失败的输入延迟测试和批量输出基准。
- 对比输入 p50/p95/p99、VT MB/s、CPU paint、锁等待、分配和帧时间。
- 补充失败路径：同一帧 Composition/提交文本/Enter/Backspace 顺序、重复 build 不重复发送、队列满和 Send/Close 并发、batch 切在 UTF-8/CSI 中间、`Read` 同时返回 `n>0, err!=nil`、回复队列满、阻塞 Write、Close 与 OnExit 重入、Resize 与 Close 并发。
- macOS 实机跑 zsh、vim/less（已有功能范围内）、中文/IME、粘贴、Ctrl+C、滚动；Linux/Windows 交叉编译和测试。
- 只有 A 阶段所有回放、终端测试、竞态测试和性能回归门槛通过，才进入 B。

### B 阶段

- 先写快照并发测试、行缓存命中/失效测试、resize/scrollback/selection 回归测试。
- 对照旧实现逐格比较屏幕字符、样式、光标、选区和无障碍文本。
- 补充持续输出同时发生滚屏、环形行复用、resize、clear、选区复制、视口滚动和 style compaction；快照发布后立即 Close/Resize，验证不会读取已复用的行切片。
- 使用固定 50 MB 输出、10,000 行回滚、不同窗口大小和主题跑 benchmark；记录缓存命中率、快照复制字节数、锁等待和帧时间。
- macOS 作为完整性能验收，Linux 带字体容器做测试，Windows 至少交叉编译与单测；移动端跑回放和软键盘回显。

## 6. 已确认的架构决策

以下决策由用户在 builder 检查后确认，A/B 实现必须遵守：

1. **有界发送队列与不丢键**：保留 8MB 有界队列；普通按键、Ctrl 组合、Esc、Enter 使用保留的小额度，不能丢；超大粘贴允许截断，但必须返回明确状态并记录，不能静默丢弃；UI 线程不无限阻塞。
2. **输入直通边界**：增加终端专用实验性输入通道，在事件路由阶段直接编码并进入异步发送队列；不把“下一帧 paint 前发送”当作最终目标。
3. **实验性快照 API**：允许新增/调整终端实验性 API；UI 不直接读取 `Screen`、`Line`、`Cell` 的内部可变数据，B 阶段使用版本化快照和行级数据。
4. **统一 benchmark**：纯 ASCII、彩色 ANSI、真实 PTY 分开测量，统一输入、生命周期和渲染器；500 MB/s 是目标和回归参考，不是脱离输入类型的唯一硬门槛。
5. **Resize 生命周期**：`Conn.Resize` 不得在终端生命周期锁内阻塞；A 阶段先移出生命周期锁，B 阶段再改为有序异步 resize，保证 resize、close、on-exit 顺序一致。

## 7. 风险和默认决策

- **输入接线位置**：优先复用现有 `ui.Context`/终端控件路由，不扩展稳定的 `ui/input` API；若必须改公共输入路由，先加最小实验接口和回归测试。
- **快照复制成本**：先测实际快照字节数；如果复制成本抵消收益，采用行级 copy-on-write，而不是盲目复制整屏。
- **绘制列表复用**：只缓存终端自有、可验证生命周期的 ops；不缓存带外部可变指针的对象。缓存失效宁可多画，不能画旧内容。
- **基线噪声**：所有性能结果至少 3 次，报告中同时记录机器负载；`ui/editor` 的独立性能阈值失败不得阻塞终端性能判断，但合并前要单独说明。
