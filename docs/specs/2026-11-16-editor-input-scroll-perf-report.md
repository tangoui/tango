# 编辑器输入与滚动分配优化

日期：2026-11-16。
范围：本轮仅 `ui/editor/minimap.go`、`minimap_chars.go`、`monarch/lexer.go`，不改 GPU、宿主、公共 API、默认功能或工作预算。

## 基线与方法

- 基线：`b7a963c`，已包含 `3978731` 完整括号 token 缓存，**没有重复合入该候选**。
- 优化：`3ac1544`、`c4631e1`、`b94e454`；最终提交号以分支历史为准。
- Apple M4，Go 1.27.2，macOS 26.6，darwin/arm64；程序运行时默认 GOMAXPROCS=10，不设置特殊 GOGC 或超时倍率。
- 初始 CPU/alloc profile（负载约 26）仅用于找热点，不用于证明耗时收益：小地图 token 查询约占 alloc_space 的 11.6%，字符格子临时数组约 8.4%，词法重复匹配和转换也占有成本。profile 含初始化与后台高亮，比例不冒充稳态每帧占比。
- 新增微基准使用真实 Highlighter、View、词法 grammar；准备好 fixture 后只计目标操作，不把字体初始化或 GPU 渲染混入小地图准备成本。
- 端到端使用固定 before/after 二进制、相同输入、5 轮三臂交替：baseline、optimized、baseline-aa。使用既有 `ui/editor/perfab/arms.sh`；每个新进程前后记录负载，任一采样 >=6 则整轮作废重跑。输入、滚动、CPU 和 GPU 等待分列；GPU 基准是离屏完成，不冒充实际屏幕呈现。

## 改动与微基准（各 3 次）

| 路径 | 优化前 | 优化后 | 判定 |
|---|---|---|---|
| 未变化的 81 行小地图准备 | 36.99–38.50µs，81,768B，405 allocs | 22.24–22.46µs，64B，2 allocs | 约减少 41% 时间和几乎全部临时分配 |
| 120 列字符位图栅格化 | 2.855–3.043µs，12,272B，9 allocs | 2.474–2.543µs，4,144B，2 allocs | 约减少 17% 时间、66% 分配字节 |
| 4KB 纯 RE2 长行 | 30.87–31.78µs，约 36KB，8 allocs（129–133MB/s） | 19.78–19.97µs，约 300B，5 allocs（205–207MB/s） | 不再为 RE2 创建无用的 rune/index |

这些是指定操作的微基准，不等于整帧或整个编辑器快了相同比例；总体收益以同机端到端成对结果为准。

### 小地图 scratch

`PeekTokenRange` 原来每行从 nil 切片追加 token，即使缓存行完全不变也有多次增长分配。现在 `minimapState` 保存一个只供本视图即时查询的 scratch；每个真正缓存的 `miniLine.tokens` 仍 `slices.Clone`，防止下行覆盖上行 token。采样行 keep map 复用并每次清空；准备结束清理 scratch 的 token 引用。编辑、主题、lexer 状态等失效条件不变。

### 字符位图

去掉临时 cell 列表：先做无分配的 grapheme/列宽测量，再直接向最终位图栅格化。`colorAt` 仍只在绘制时按递增字节位置调用一次，不能在宽度测量时再次调用，因其持有 token 游标。保留 1x/2x、中文、tab、emoji、组合字符、非法 UTF-8、U+0080 不绘制和尾空白裁剪行为。

### 词法 rune 索引

只有规则实际进入 Backtrack 匹配（已通过行首与首字节过滤）且剩余文本超过原 `longLineBytes` 阈值时，才构造整行 rune/index 缓冲。RE2 规则完全不需要它。字节起点仍用 `lr.index[pos]` 映射，现有 budget、跨行状态、嵌入语言和超时/截断策略不变；不新增 lexer 专用快路径。

## 正确性回归

- Task 1 红灯：预热小地图 405 次分配 >12；改后 2 次。
- Task 2 红灯：120 列位图 9 次分配 >2；改后 2 次。
- Task 3 红灯：同 grammar 长行 8 次、短行 5 次；改后都为 5 次。
- 缓存所有权测试：编辑下一行、重建新主题后旧缓存行的 token、bitmap 和文字均不变。
- UTF-16 测试：先 RE2 消耗 300 字节，再实际 Backtrack 匹配 `世😀`；后续 token 的字节位置 307、UTF-16 列 303 保持正确。
- 真实回调顺序测试：tab、中文、组合字符、emoji、U+0080、非法 UTF-8 混排，callback 仅一次且 byte offset 依次为 0、2、5、8、14。
- 所有 minimap 黄金像素/strip 增量/折叠与 view zones/主题失效和 `TestViewDamageVerified` 通过，未更新 goldens。
- Monarch、regex、langs 全部 fixture/degrade/budget 测试通过。
- 每项产品改动后均运行 `CGO_ENABLED=1 go test ./...`，三次均通过。

## 保持不变的验收边界

- 不以一次 wall-clock 测试尖峰证明产品算法慢；没有修改 `gateLimit`、最小工作量或超时常量。
- 不新增或改变 MyGo 对照目标：现有已合入的 Go 快路径留在基线，当前无 MyGo 新实测就不声称本轮进一步超过它。
- Monaco GPU-complete、Windows 真机、中文 IME 实窗等原报告未验证项，不因本轮微基准收益而改判通过。

## 五轮三臂端到端结果

有效轮次共 5 轮，负载 2.49–3.95，未因高负载放宽门槛。下表为逐轮指标的中位数；CI 是现有驱动对配对比值给出的 95% bootstrap 区间。不是单次最快值。

| 场景 | 指标 | baseline | optimized | 比值 / 95% CI | 判断 |
|---|---|---:|---:|---|---|
| TS20k 输入 | p95 ms | 16.460 | 11.290 | 0.686 / 0.608–1.591 | 未证明稳定加速；原版重复臂 p95 同样为 11.320，A/A 噪声 31.2% |
| TS20k 滚动 | p99 ms | 17.110 | 16.860 | 0.985 / 0.895–1.305 | 统计上未判定 |
| TS20k 滚动 | fps（离屏 GPU 完成） | 115.3 | 119.3 | 1.035 | 小幅点估计收益，不宣称显著改善 |
| 1MB 单行换行输入 | p95 ms | 16.200 | 11.620 | 0.717 / 0.693–1.386 | 未证明稳定达标：优化臂 5 轮中仍有 16.120、16.630ms，超过 16ms |
| 百万行输入 | p95 ms | 9.975 | 10.010 | 1.004 / 0.584–1.145 | 点估计近似不变，不能声称变快 |
| 百万行局部滚动 | p99 ms | 12.590 | 13.100 | 1.041 / 0.911–1.186 | 点估计慢 4.1%，与 A/A 约 3.8% 相近；未证明改善，也未排除 >10% 尾延迟回归 |
| 百万行局部滚动 | CPU mean ms | 3.459 | 3.448 | 0.997 / 0.962–1.009 | CPU 工作近似不变，99.5% 帧仍局部重绘 |

**判定边界：** 本轮能确认的是热点和整帧分配减少；成对时延数据不足以宣称整体输入/滚动显著加速、长行稳定达标或通过所有 10% 回归门槛。需要更多轮次或更可控的平台/呈现测量来收窄 CI，不修改门槛，也不把 GPU 等待归为已解决。

## 终审与剩余项

- 唯一一次 fresh 独立审阅未发现已验证的 Critical/Important 正确性问题，确认 token scratch 不被缓存行/strip 持有、两遍栅格化像素及 callback 语义一致、rune 延迟分配不改变匹配尝试和预算计费。
- Minor（延后）：退出时 `clear(m.tokenScratch)` 只清理最后结果长度，底层数组尾部可能保留早先 token 的类型字符串。未发现显示或语法正确性影响；后续可清理完整容量，并加引用回归测试。当前不宣称完全清除了所有旧 grammar 引用。
- 所有新代码 `gofmt` 干净；darwin/Linux/Windows 编辑器及 editor-demo 的 `go vet` 通过；`apitxt -check` 82 项最新，无 API 改动。
- 完整 `go test -race ./ui/editor/... -count=1` 中，编辑器、buffer、diff、diffview、highlight、keymap、langs、regex、theme、when 均通过；唯一失败是本轮新增的 Monarch 精确分配次数断言，并非数据竞争。根因是 Go `sync.Pool.Put` 在 race 模式随机丢弃 1/4 对象，标准库正则的长度相关工作缓冲因此产生额外分配。单独重复 12 次可复现。
- 将精确分配断言原样移到 `!race` 测试文件，性能门槛不放宽；普通/race 模式都保留长短行 token、状态及 UTF-16 正确性测试。两种构建定向重复 12 次均通过，唯一失败包完整 `go test -race ./ui/editor/monarch -count=1` 复测通过。其他已通过包没有产品或测试修改，未重新消耗约 8 分钟把整套 race 再跑一遍。
- 突变验证：通过 Go overlay 恢复基线 eager-rune 实现后，新文件中的原分配断言仍失败（长行 8 次、短行 5 次），确认没有隐藏性能回归。
- 本轮没有把“时延回归 CI 尚未收窄”改写为通过，因此保留在隔离分支，未合并或推送；后续集成前需接受该测量限制或进一步定点复测。
