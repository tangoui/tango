# 多语言（i18n）

状态：第一期已实现（`i18n/` 包、各桌面平台的系统语言、原生菜单标准项与对话框默认按钮本地化）。第二期的 ui 组件接线与 zh-TW / ja 组件语言包已完成（2026-11-12，见第 5.1 节）；uihost 跟随系统语言等其余各项仍待做。

## 1. 目标与分层

```
应用代码 ── i18n.T / i18n.N / i18n.Locale / i18n.SetLocale / i18n.OnChange
               │
           i18n（根下公开包，不依赖 tango 根包）
               │  系统语言来源（按优先级）：
               │   1. i18n.Init(app) 后 app.Backend() 实现的 platform.Locales
               │   2. 桌面后端包 init 时登记的 platform.SetLocaleSource（darwin / windows）
               │   3. 环境变量 LANGUAGE → LC_ALL → LC_MESSAGES → LANG
               ▼
internal/platform/locale.go      Locales 可选接口 + 来源登记 + 环境变量解析（新文件，未改契约文件）
internal/platform/rolenames      菜单标准项、对话框默认按钮的四语文案表（按平台用词）
internal/platform/{darwin,windows,linux}  PreferredLocales 实现；菜单/对话框文案改为查表
```

- **i18n 不强依赖 `*tango.App`**：桌面上只要程序 import 了 tango 根包（根包会 import 当前平台后端包），后端包的 `init` 就登记了系统语言来源，`i18n.Locale()` 在 `tango.Run` 之前、甚至不建 App 也能用。单元测试、命令行工具没有后端时退回环境变量。
- `i18n.Init(app)` 是可选的：它让 i18n 优先使用 `app.Backend()` 上的 `platform.Locales`。桌面上效果与不调用相同；给第二期的 iOS / Android 后端用（它们的答案依赖运行中的宿主，只能实现在 Backend 值上）。参数类型是 `i18n.AppBackend`（`interface{ Backend() platform.Backend }`），`*tango.App` 天然满足，所以 i18n 不 import 根包、没有循环依赖。

## 2. API

```go
package i18n

const DefaultLocale = "en"                 // 一切回退的终点
var Builtin = []string{"en", "zh-CN", "zh-TW", "ja"} // Tango 自带文案的语言

// 系统语言与当前语言
func Preferred() []string                  // 系统首选语言，BCP 47，按用户偏好排序；首次读取后缓存
func Locale() string                       // 当前生效语言：SetLocale 覆盖值，否则 Match(Preferred(), Supported())
func SetLocale(tag string)                 // 应用覆盖（先与 Supported 匹配，"zh-Hant"→"zh-TW"）；"" 恢复跟随系统
func Refresh()                             // 重新读取系统语言；macOS/Windows 上系统语言变化时 Tango 自动调用（见 5.2），Linux 需应用自己调
func OnChange(fn func(locale string)) (cancel func()) // 生效语言变化时回调，在引发变化的 goroutine 上同步调用
func Init(app AppBackend)                  // 可选：使用 app.Backend() 的 platform.Locales / platform.LocaleWatcher
func Supported() []string                  // 已加载目录的语言；没加载任何目录时为 Builtin

// 语言匹配
func Canonical(tag string) string          // "zh_hans_cn.UTF-8" → "zh-Hans-CN"；"C"/"POSIX" → ""
func Match(prefs, available []string) string
func MatchOK(prefs, available []string) (string, bool)

// 文案目录
func Load(fsys fs.FS, dir string) error    // 读取 dir 下所有 <locale>.json
func T(key string, args ...any) string     // 具名参数：T("hello", "name", "Tom")
func N(key string, count int, args ...any) string // 复数，自动带 {count}

// 复数规则
type PluralRule func(n int) string
func RegisterPluralRule(lang string, rule PluralRule)
func PluralCategory(locale string, n int) string
```

全部函数并发安全（`sync.RWMutex` + 语言列表用 `atomic.Pointer` 快照；`go test -race` 有并发用例）。

### 2.1 语言匹配规则

自写匹配器，**没有引入 golang.org/x/text/language**。理由：需要的规则只有"完全相同 → 中文简繁分流 → 同语言同地区 → 同语言"，几十行能写清楚、表驱动测试能全覆盖；x/text 的 CLDR 匹配器要加依赖和约 1 MB 表数据到每个应用里，而且它的"距离"结果对 zh-HK 等情形不直观，还得再包一层。以后要支持更多复杂语言（sr-Latn/sr-Cyrl 等）再评估换 x/text。

对 `prefs` 中每一项依次尝试，命中即返回：

1. 规范化后完全相同（`zh_TW.UTF-8` 等 POSIX 写法也会规范化）；
2. 中文按书写系统分流：`zh`、`zh-CN`、`zh-SG`、`zh-Hans`、`zh-Hans-*` → 简体条目（zh-CN）；`zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant`、`zh-Hant-*` → 繁体条目（zh-TW）。**简繁不互相替代**：繁体用户在只有 zh-CN 的应用里会继续看下一个首选语言，最后落到 en；
3. 同语言同地区（忽略书写系统）；
4. 同语言，优先无地区的条目（`en-GB` → `en`）。

都不中时返回 `DefaultLocale`（en，若 available 里有），否则 available[0]。

`Locale()` 从 `Supported()` 里选：应用加载了目录就只在应用支持的语言里选（保证应用文案与原生菜单语言一致）；没加载目录时从 `Builtin` 里选。

### 2.2 文案文件格式

`i18n.Load(fsys, "locales")` 读取 `locales/*.json`，文件名即语言标签（`zh-CN.json`，也接受 `zh_CN.json`）。每个文件是**扁平**的 JSON 对象：key → 字符串；复数项的值是以 CLDR 复数类别为键的对象，必须有 `other`。

```jsonc
// locales/en.json
{
  "hello": "Hello, {name}!",
  "files": {"one": "{count} file selected", "other": "{count} files selected"},
  "braces": "Use {{name}} for a placeholder"
}
// locales/zh-CN.json
{
  "hello": "你好，{name}！",
  "files": {"other": "已选择 {count} 个文件"}
}
```

```go
//go:embed locales
var locales embed.FS

i18n.Load(locales, "locales")
i18n.T("hello", "name", "Tom")      // 你好，Tom！
i18n.N("files", 3)                  // 已选择 3 个文件
i18n.N("inbox", 2, "name", "Ann")   // 复数 + 其他具名参数
```

- 参数统一用**名/值成对**的可变参数（不支持 map）；`{name}` 没有对应参数时原样保留；`{{`、`}}` 表示字面花括号。参数个数为奇数时开发期警告一次。
- 回退：当前语言 → `DefaultLocale`（en）→ key 本身。开发构建（`-tags tango_dev`，`tan dev` 自动加）里每个缺失的 (语言, key) 只在日志里警告一次；发布构建不输出。
- 同一语言可多次 Load，后加载的 key 覆盖先加载的（可以先加载基础包再加载覆盖包）。Load 可能改变 Supported，从而改变 Locale，会触发 OnChange。
- `T` 遇到复数项用 `other` 形式；`N` 遇到普通字符串项对任何数量都用它。

### 2.3 复数

内置规则（整数）：zh/ja/ko/vi/th/id/ms/lo/my/km/yue 只有 `other`；en/de/nl/北欧/it/es/ca/el/hu/tr/bg/af 等是 `one`(n==1)/`other`；fr/pt/hi/bn/fa 是 0 和 1 为 `one`。未登记的语言按英语规则。`N` 用"文案实际来自的语言"的规则（回退到 en 的文案用 en 规则）。扩展点：`i18n.RegisterPluralRule("ru", func(n int) string {...})`，类别取值 zero/one/two/few/many/other；目录里缺这个类别时用 `other`。

## 3. 平台系统语言

| 平台 | 实现 | 文件 |
|---|---|---|
| macOS | `[NSLocale preferredLanguages]`（objc 运行时，autorelease pool 内调用，任意线程可调），返回如 `zh-Hans-CN` | `internal/platform/darwin/locale.go` |
| Windows | `GetUserPreferredUILanguages(MUI_LANGUAGE_NAME)`，多字符串解析在无平台标签的 `localeplan.go`（有单测） | `internal/platform/windows/locale_windows.go`、`localeplan.go` |
| Linux | 环境变量（LANGUAGE、LC_ALL、LC_MESSAGES、LANG）。没有绑 `g_get_language_names`：它读的就是这几个环境变量，只多出 `zh_CN.UTF-8`/`zh_CN`/`zh` 这类展开项和 `C`，对匹配没有帮助 | `internal/platform/linux/locale_linux.go` |
| iOS / Android | **本期不做**（另一个会话在改这两个后端）。第二期在 Backend 值上实现 `platform.Locales`（iOS 同样是 `NSLocale preferredLanguages`；Android 走 JNI `LocaleList.getDefault()` 或宿主启动时传入），应用调用 `i18n.Init(app)` 即可生效 | — |

darwin、windows 后端在包 `init` 中调用 `platform.SetLocaleSource`，并在后端类型上实现 `PreferredLocales()`；linux 只实现方法（环境变量本来就是 i18n 的兜底）。

## 4. 原生菜单标准项与对话框按钮

`internal/platform/rolenames` 存四种语言（en、zh-CN、zh-TW、ja）× 三套平台用词：

- `mac.*`：苹果官方用词。简体："关于 %s""隐藏 %s""隐藏其他""全部显示""退出 %s""撤销""重做""剪切""拷贝""粘贴""删除""全选""编辑""窗口""最小化""缩放""前置全部窗口""关闭窗口""进入全屏幕"，提示框默认按钮"好"。繁体（台湾）："結束 %s""還原""拷貝""縮到最小""將此程式所有視窗移至最前"等。日文："%sを終了""しまう""すべてを手前に移動"等。
- `win.*`：微软用词（"退出/結束/終了""复制/複製""关闭""确定""关于 %s"、日文"%s のバージョン情報"）。
- `gtk.*`：GNOME/GTK 用词，带助记符（"退出(_Q)""复制(_C)""确定(_O)"）。

另有 ok/cancel/yes/no 四个按钮文案（目前各平台只用到 ok，其余备用）。`rolenames.Text(key)` 按 `i18n.Locale()` 取值（先与四种语言匹配，未知语言用英文；未知 key 原样返回），`rolenames.Format(key, appName)` 再替换 `%s`。

**语言变化不实时刷新已构建的菜单**：菜单标签在后端构建菜单时取值，`SetLocale` 之后需要应用再设置一次菜单（`menu.SetAppMenu` 或 `Menu.Update`）才会变。对话框默认按钮每次弹出时取值。

**macOS 补充**：AppKit 自己维护的几项——"撤销/重做"（NSUndoManager 校验菜单时会改标题）、编辑菜单里系统插入的"自动填充/开始听写/表情与符号"、窗口菜单里系统插入的"填充/居中/移动与调整大小"等——跟随的是**应用包的本地化声明**而不是 Tango 的表。裸二进制（`go run`）没有 Info.plist，这些项显示英文；把同一二进制放进 Info.plist 声明了 `CFBundleLocalizations`（en、zh-Hans、zh-Hant、ja）的 .app 后实测全部变成中文。`cmd/tan` 生成的 Info.plist 目前只有 `CFBundleDevelopmentRegion`，第二期补 `CFBundleLocalizations`（cmd/tan 本期不能动）。

### 5.2 系统语言变化监听、菜单重建、Info.plist 本地化（2026-11-12）

对应第 5 节第 4、5、6 项。

- **平台契约**（`internal/platform/locale.go` 末尾追加）：可选接口 `LocaleWatcher { WatchLocales(fn func()) (cancel func()) }`；与 `SetLocaleSource` 对称的 `SetLocaleWatch` / `LocaleWatch`，桌面后端包在 `init` 里注册，i18n 不需要 `tango.App` 也能订阅；`LocaleListeners` 是后端共用的回调集合。
- **macOS**（`darwin/locale_watch.go`）：`TangoLocaleObserver` 同时观察默认中心的 `NSCurrentLocaleDidChangeNotification`（取 Foundation 导出常量，值不是它的名字）与分布式中心的 `AppleLanguagePreferencesChangedNotification`（系统设置改首选语言时广播）。通知由主 run loop 派发，回调在主线程；`tango.Run` 之前不会到达。
- **Windows**（`windows/locale_watch_windows.go`）：`WM_SETTINGCHANGE` 且 lParam 为 `"intl"`。接入点是已有的 `integration_windows.go` 的 `systemMessage`（隐藏应用窗口收到的广播）里加的一行 `localeSettingChanged(wstr(lp))`，所以只在应用运行时生效，回调在主线程。
- **Linux**：没有标准的变化通知（语言来自环境变量 / 会话设置，改了一般要重新登录），不实现 `LocaleWatcher`；需要时应用自己调 `i18n.Refresh()`（例如窗口重新获得焦点时）。
- **i18n**（`i18n/watch.go`）：第一次读系统语言（`Preferred` / `Locale` 以及基于它们的一切，例如菜单角色标签）时订阅注册的 watcher；`Init(app)` 时若 backend 实现了 `LocaleWatcher` 就改订它。回调就是 `Refresh`：生效语言真变了才通知 `OnChange`。只注册 `OnChange` 不会启动监听，所以别的包可以在 `init` 里注册而没有副作用。测试用 fake 后端（`fake/locale.go` 的 `SetSystemLocales` 模拟用户改系统语言）。
- **菜单**（`sys/menu/relocalize.go`）：`init` 里注册 `i18n.OnChange`，变化时在新 goroutine 里把所有已挂载的菜单（菜单栏、窗口菜单、托盘菜单）重新 `push` 一遍；后端构建原生菜单时按当时的语言翻译角色项，因此标准项随之更新。右键菜单打开时才构建，不需要处理。依赖方向 `sys/menu → i18n`，i18n 不依赖 menu，无循环。系统语言变化与 `i18n.SetLocale` 都会触发。
- **Info.plist**（`cmd/tan/build.go` 的 `infoPlist`）：写 `CFBundleLocalizations = [en, zh-Hans, zh-Hant, ja]`（与 `Builtin` 对应），`CFBundleDevelopmentRegion = en`（原来就有）。AppKit 自己命名或追加的菜单项（撤销/重做、自动填充、开始听写…、表情与符号、进入全屏幕等）只会翻译成 bundle 声明了的语言：实测系统语言为简体中文时，没有该键的编辑菜单是 "Undo, Redo, …, AutoFill, Start Dictation…, Emoji & Symbols"，加上后是"撤销、重做、…、自动填充、开始听写…、表情与符号"。tan.json 目前没有配置本地化语言的字段，四种是固定默认值；应用的目录有更多语言时需要再加配置项。iOS 的 Info.plist（`build_ios_app.go`）本期未改。

- **此前已有的分组**（第一、二期）：`Calendar`、`Carousel`、`Image`、`ColorPicker`、`Tour`、`QRCode`、`Table`、`ProTable`、`Transfer`、`Upload`、`Markdown`、`Form`、`MarkdownEditor`、`Command`、`A11y`、`Chart`（含 `Total`、`Conversion`）、`Mobile`（`PullToRefresh`、`ReleaseToRefresh`、`Refreshed`、`TapToRetry`、`DayFmt`、`HourFmt`、`MinuteFmt`，供 `ui/mobile` 使用）。
