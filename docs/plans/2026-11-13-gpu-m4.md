# GPU 渲染 里程碑 4（Linux OpenGL 3.3 + GLSL 后端）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Tango 自绘 UI 在 Linux 上经 OpenGL 3.3 core（GTK3 `GtkGLArea`）渲染：着色器编译器新增 GLSL 330 / GLSL ES 300 后端，`ui/gpu/gl` 实现与 Metal、D3D11 设备同一帧契约的 `gpu.Device` 与呈现器，Linux canvas 交出 `GtkGLArea`，uihost 接上。

**Architecture:** `ui/shader/glsl` 从同一份 IR 输出顶点、片元两份 GLSL 源码；`ui/gpu/gl` 经 purego 调 GL（Linux 用 libepoxy 取函数指针，兼容 GLX 与 EGL；darwin 用 OpenGL.framework，**仅用于本机实测**），设备语义以 `ui/gpu/metal/metal_darwin.go` 顶部设计注释与 M3 报告第 3 节对照表为准。渲染进常驻的离屏 FBO，呈现器在 `GtkGLArea` 的 `render` 信号里把它 blit 到 GLArea 的帧缓冲。

**Tech Stack:** Go 1.27、purego v0.11.1（已是依赖）、OpenGL 3.3 core / GLSL 330、libepoxy、EGL（surfaceless，无头测试）、CGL（darwin 测试）、GTK 3.24、自研着色器编译器 `ui/shader`。

**Spec:** `docs/specs/gpu-renderer.md`（里程碑 4；6.3–6.6、6.8）；对照 `docs/specs/gpu-renderer-m3-report.md`（第 3 节语义对照表）、`docs/specs/canvas-surface.md`（"GPU 呈现"一节）。

## Global Constraints

- 模块 `github.com/tangoui/tango`，Go 1.27；桌面无 cgo；**不新增外部依赖**（GL/EGL/GTK/CGL 全部经已有的 purego）。
- 颜色按预乘 alpha、sRGB 空间混合，与 `paint.CPU` 一致；比对阈值：几何与填充每通道 ≤ 2，文字与图片缩放 ≤ 4，超阈值像素 ≤ 0.5%（`gpuconf.Conformance` 已内置）。
- 帧契约（`ui/gpu/frame.go`）不改语义；GL 设备与 Metal 逐条一致，差异写进报告的对照表（格式同 M3 报告第 3 节）。
- 着色器继续单个 quad 着色器加 `Kind`；改结构后 `go generate ./ui/gpu/gen/`。
- **离屏目标按"行 0 = 顶行"存放**：顶点着色器输出 `gl_Position = vec4(p.x, -p.y, 2.0*p.z - p.w, p.w)`（y 翻转、深度 0..1 → -1..1）。这样纹理采样（左上原点）、`glScissor`/`glViewport`/`glReadPixels`/拷贝的 y 都直接用帧契约的左上坐标，无需换算；只有呈现时 blit 到窗口帧缓冲需要翻转一次。
- **线程**：GL 调用只在上下文当前的线程上。无头设备（`gl.NewDevice`）自带一个 `runtime.LockOSThread` 的专用 goroutine，所有方法经它执行；呈现器的设备在调用者线程（uihost 保证是 GTK 主线程，在 `CanvasFrame` 内）先 `gtk_gl_area_make_current` 再执行。
- 构建标签：GL 设备代码 `//go:build linux || darwin`；darwin 的 CGL 上下文只服务于测试与本机验证，uihost 在 darwin 仍只用 Metal；其他平台的桩返回 `ErrUnsupported`。
- **文件归属**：可改 `ui/shader/**`、`ui/gpu/**`（`ui/gpu/metal` 不改；`ui/gpu/d3d11` 只做 Task 2 的搬移）、`internal/platform/linux/canvas*`、`internal/platform/canvas.go`（只追加 `CanvasGL`）、`internal/platform/fake/`（只追加）、`uihost/gpu*.go`、相关文档。不改 `ui/paint`、`ui/text`、`ui/runner.go`、`ui/window.go`、`internal/platform/{ios,android,mobilecanvas}`（min-95 在做）。
- **不 git commit / push / add**（tango 的提交只由会话 min-ab 做）；每个任务结束把改动路径与验证结果交给控制者。
- 每个任务结束：darwin `go build ./... && go vet ./ui/... ./uihost/...`；`GOOS=linux go build ./... && GOOS=linux go vet ./ui/... ./uihost/...`；`GOOS=windows go build ./...`。
- **Linux 实测环境**：podman 镜像 `localhost/tango-linuxtest:bookworm`（aarch64，含 GTK 3.24、Mesa 22.3 llvmpipe、libEGL、libepoxy、Xvfb）。运行方式固定为：

## Review Focus

1. 机器没有可用的 GL 3.3（虚拟机无 3D、SSH 转发 X、老显卡）：`GtkGLArea` 实现报错，`UseGLArea` 返回错误，窗口留在 CPU 路径，不崩溃 —— Task 5 `TestUseGLAreaUnavailable`（容器内 `GDK_GL=disable`）。
2. HiDPI（`GDK_SCALE=2`）：GLArea 帧缓冲按设备像素，`present` 的 size = round(逻辑尺寸×scale)，画面不模糊、不只占四分之一 —— Task 6 `TestPresenterScale2`。
3. 窗口最小化（尺寸 0）与超过 `GL_MAX_TEXTURE_SIZE` 的窗口：前者不提交、返回 nil；后者返回包装 `gpu.ErrTargetTooLarge` 的错误且不计故障 —— Task 3 `TestGLZeroSize`、`TestGLTargetTooLarge`（用 `maxTextureOverride` 测试钩子把上限压到 256）。
4. 驱动拒绝着色器或链接失败：`NewDevice`/`NewPresenter` 返回带 info log 的错误，uihost 回退 CPU —— Task 2 `TestCompileErrorIncludesLog`。
5. uniform 结构在 std140 下与 Go 布局不同：生成器报字段名与两边偏移 —— Task 1 `TestStd140LayoutMismatch`。
