# WebView keyboard automation implementation plan

Spec [WebView keyboard automation](../specs/2026-11-26-web-key-design.md).

For each implementation task, observe the regression test fail, implement the behavior, rerun it, check the diff and commit with the Tango author.

1. **Wire operation and MCP tool.** Add server tests to `internal/automation/server_test.go` for the parsed chord, wrong window type, missing window and backend errors. Add an MCP test in `cmd/tan/mcp_web_test.go` for the selected window and transmitted chord. Wire `web_key` through the server, development host and optional platform interface. Run `go test -tags tango_dev ./internal/automation ./internal/devfeat` and `go -C cmd/tan test ./... -run TestWeb`.
2. **Shared key data and macOS delivery.** Test ANSI codes, shifted characters and macOS key equivalents. Build native NSEvents with the selected window number, route enabled native menu actions and send unconsumed input to WKWebView. Run `go test -tags tango_dev ./internal/platform/darwin` and exercise a background WebView with MCP.
3. **Windows delivery.** Test virtual keys, CDP payloads and accelerator selection in the untagged Windows helper tests. Connect the planner to WebView2 and the existing menu command path. Run `go test ./internal/platform/windows` and tagged Windows vet.
4. **Linux delivery.** Test keyvals and modifier masks in the untagged Linux helper tests. Deliver GDK key events using the target GtkWindow's accelerators and WebKitGTK input. Run `go test ./internal/platform/linux` and tagged Linux vet.
5. **Usage and smoke coverage.** Document the tool in `docs/mcp.md`, the wire operation in `docs/automation.md` and the new workflow in `skills/tango/references/verify.md`. Add a repeatable desktop regression fixture that verifies key events, actual text input, native menu activation and Edit role behavior. Capture the macOS MCP results under the requested output directory.
6. **Branch verification.** Run root and CLI Go tests, tagged tests, Windows and Linux vet with the development tag as well as default builds, gofmt checks including tagged files and `go run ./internal/cmd/apitxt -check`. Record evidence, platform coverage and remaining limitations. Keep the commits on the local feature branch.
