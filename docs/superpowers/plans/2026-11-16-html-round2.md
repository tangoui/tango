# HTML 第二轮：调用内存储与失败回溯前缀过滤

基线 `086a8878f08c94d65484f251fe72832ee335c0a3`，分支 `perf/html-round2-20261116`，继续已批准的 HTML 性能优化。证据目录 `/Users/admin/min/outputs/tango-html-round2-20261116/`。

## 已确认的诊断与方案

新基线相关四包普通测试通过。混合 HTML 的分配 profile 指向 `myTokenize` 的循环内 `groupMatching`/分组项，以及空匹配、默认字符的单捕获切片。匹配和时钟检查仍有 CPU 成本；当前高负载 profile 仅用于定位，不作为合格的速度对照。

在每次 `myTokenize` 调用内复用一个分组容器和最多四项的分组存储；首次真正使用小分组时才按需分配，小缓冲容量不足时增长，大于四组继续使用独立动态存储。未匹配和空行复用已有调用帧的单捕获槽。每次递归调用有独立存储，不使用全局缓冲或跨行池，不改变完整捕获 API、HTML grammar、JS/CSS 嵌入、预算和超时逻辑。

分组容器只有前一组耗尽后才能复用；现有非法嵌套/空组/零进展检查保持。保留动态 token、状态替换、goBack、@rematch、Unicode/非法 UTF-8、前缀目标切片和并发语义。若局部存储逃逸到堆，需以分配/字节结果重新判断方案，不把更大调用帧当作收益。

首次固定数组方案被空行预算拦截：编译逃逸记录确认小数组会无条件堆分配，空行仍为3次。改为上述按需小缓冲，保持无分组路径不承担额外分配；原失败日志保留。

小缓冲的五对低负载样本分配次数减少约20%，混合耗时中位数仅降低约2%，因此继续优化失败回溯的前缀判断：从 regexp2 对已翻译、已锚定表达式生成的只读首字符集合提取 ASCII 必要条件，最多分析512字节源码，Unicode/空输入/不支持情况保留原引擎。只在公共匹配入口提前排除不可能的 ASCII 首字节，不改内部超时确认实现或完整捕获结果。

Monarch 原有的单字节必要前缀过滤将区分顶层选择与括号/字符类/转义中的竖线，保留可选首字符、顶层其他分支及 ignoreCase 时的保守回退；含竖线时的额外扫描限512字节，inline options、注释和非JS分组扩展保留原回退，避免改变标点解析方式后误判。编译时额外分析的时间/分配需单列，不能将热匹配收益宣称为冷编译收益。
