# 下行轮询通道（down:poll）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Tango 页面收消息（Go→JS）在 macOS 上走“短响应 + 立即重发”的轮询通道，承载所有 `Surface.Send` 消息和 ipc 字节帧，Eval 只作兜底，下行三项吞吐不低于 Wails v3.1.0。

**Architecture:** 新包 `internal/downq` 持有每个页面的下行队列：分配序号、按批写出轮询响应、确认、退回 Eval、看门狗、栅栏。核心 `*tango.Surface` 把 `Send`/`Eval` 接到它上面，页面侧在 `coreShim` 之后注入 `downShim`（轮询循环、按序号重排、栅栏）。ipc 字节帧经 `lane.State` 的新通道 `down:poll` 进入同一个队列；`down:scheme` 删除。

**Tech Stack:** Go 1.27（无新依赖）；purego 的 darwin 后端；`@tangoui/runtime`（TypeScript）；node 内置 test runner；`automation` 包驱动真实 WKWebView 的 e2e。

**Spec:** `docs/superpowers/specs/2026-11-14-down-poll-design.md`（同目录的 IPC 总规格 `docs/specs/2026-11-13-ipc-duplex-streams.md` §6 是背景）。对比基准与 Wails 数据：`/Users/admin/min/ipc-bench/REPORT.md`、`/Users/admin/min/ipc-bench/`（Wails 基准程序与脚本）。

- 端点：`GET <资源来源>/__tango/lane/poll?gen=<世代>&tok=<令牌>&ack=<已交付最大序号>`，响应 `200`，`Content-Type: application/octet-stream`、`X-Content-Type-Options: nosniff`、`Cache-Control: no-store`。
- 响应体（大端）：`batch := firstSeq:u64 | count:u32 | item*count`，`item := kind:u8 | len:u32 | payload[len]`；kind `0` 字符串消息（UTF-8），`1` 字节包（现有通道包格式），`2` 栅栏（载荷为栅栏编号 u64）。
- 挂起上限 25 s（到时返回 `count=0` 的空批）；每批上限 4 MiB 或 4096 项，先到者为准（单项超过 4 MiB 时单独成批）；看门狗阈值 1 s。三者都是包级变量，测试可改。
- 序号：每个下行世代从 1 开始，消息、字节包、栅栏共用一个序列；Eval 兜底也带序号。
- 世代：页面加载完成（`SurfaceLoaded`，可信页面）开始新世代；`SurfaceNavigating` 或 `Navigate` 结束当前世代，丢弃未写出和未确认的项。
- `TANGO_IPC_LANES_DARWIN` 取值表（大小写不敏感、忽略首尾空白）：未设置 → `up:post`（`down:poll` 在 Task 9 达标前不默认开）；`1`/`all` → 两者；`up` → 只 `up:post`；`down` → 只 `down:poll`；`0`/`false`/`off` → 无。`TANGO_IPC_LANES=0`、`Options.DisableFastLanes` 优先关闭全部。`all` 在任何构建里都生效。
- 开启 `down:poll` 还要求：页面来自资源来源、后端报告该能力。**不要求**注册了 `OnBinary`（字符串消息不依赖它）；字节包只在 ipc 用到通道时才有。
- `Surface.Eval` 的承诺不变：与 `Send` 保序（设计 5.9 栅栏）。
- 只改 macOS 后端；iOS、Windows、Linux、Android 后端不报告 `down:poll`，行为不变（编译和 vet 必须通过）。
- 每个任务结束：`go build ./... && go vet ./...`；`GOOS=windows go vet ./...`、`GOOS=linux go vet ./...`；改动包的 `go test -count=1` 全过；改动的 Go 文件 `gofmt -l` 无输出；改了 runtime-js 的任务另跑 `cd runtime-js && npm test && npm run contract:check`。

## Review Focus

1. **页面长时间不取消息**（同步卡 6 s、窗口被遮挡或最小化）：消息不能丢、不能乱序，也不能让 Go 内存无限增长前没有任何回退 —— Task 1 `TestWatchdogFallsBack`、Task 8 `TestPollStall` 与 `TestPollOccluded`。
2. **轮询中途失败**（响应被 WebKit 中断、CSP 拦截、故障注入）：已写出但未确认的消息必须经 Eval 补发，且不重复 —— Task 1 `TestFailResendsUnacked`、Task 8 `TestPollFaultNoLoss`。
3. **页面自己重载**时旧世代的队列与挂起请求：旧请求在 1 s 内结束、goroutine 回到基线，新页面从序号 1 开始 —— Task 1 `TestNewGenerationEndsPoll`、Task 8 `TestPollReloadNoLeak`。
4. **`Send` 与 `Eval` 交错 + 脚本抛异常**：页面看到严格的 a、b、c 顺序，抛异常后后续消息照常交付 —— Task 2 `downshim: barrier releases after throw`、Task 8 `TestEvalOrderedWithSend`。
5. **单条消息超过每批上限**（例如 8 MiB 的 JSON 回复）：单独成批送达，不卡住队列 —— Task 1 `TestOversizeItemAlone`。

**Files:**
- Create: `internal/downq/downq.go`、`internal/downq/http.go`
- Test: `internal/downq/downq_test.go`、`internal/downq/http_test.go`

**Interfaces:**
- Produces:
  - `type Kind uint8`；常量 `Msg Kind = 0`、`Packet Kind = 1`、`Barrier Kind = 2`
  - `type Item struct { Seq uint64; Kind Kind; Data []byte }`
  - `var HoldMax = 25 * time.Second; var BatchBytes = 4 << 20; var BatchItems = 4096; var WatchdogAfter = time.Second`
  - `func New(fallback func(items []Item)) *State` —— `fallback` 在持锁时按序号顺序调用，必须不阻塞（核心把它转到主线程）；每次调用的 items 序号连续。
  - `func (s *State) Start(enabled bool) (gen uint64, tok string)` —— 开新世代，结束旧世代（挂起请求立即返回 `410 Gone`），序号重置为 0；`enabled=false` 时 `tok==""`，所有项直接走 fallback。
  - `func (s *State) End()` —— 结束当前世代：丢弃待送和未确认项，挂起请求返回 `410`，之后的 `Push` 返回 `0` 并丢弃（核心在 `loaded=false` 期间不会调用）。
  - `func (s *State) Push(kind Kind, data []byte) (seq uint64)` —— 分配序号；轮询活跃时进队列并唤醒挂起请求，否则交给 fallback。
  - `func (s *State) Active() bool` —— 本世代已收到第一个轮询请求且未失败。
  - `func (s *State) Fail(gen, acked uint64)` —— 页面报告失败：确认 `≤ acked` 的项，其余未确认与待送项按序交给 fallback，本世代后续 `Push` 都走 fallback。
  - `func (s *State) Serve(w http.ResponseWriter, r *http.Request)` —— 处理轮询请求：校验 `gen`/`tok`（常量时间比较，不符 `403`），按 `ack` 丢弃已确认项，有待送项立即写一批并结束，否则挂起到有项、`HoldMax`、世代结束或 `r.Context()` 取消。
  - `func (s *State) Close()`
  - `func EncodeBatch(firstSeq uint64, items []Item) []byte`、`func DecodeBatch(b []byte) (firstSeq uint64, items []Item, err error)`（测试与 Task 2 的 node 测试共用格式）

**Files:**
- Create: `downshim.go`（JS 常量 `downShim`，注入顺序紧跟 `coreShim`）

- Test: `downshim_test.go`（node harness，沿用 `bridge_test.go` 的 `shimHarness` 写法，`fetch` 用假的实现）

**Interfaces:**
- Consumes: Task 1 的响应格式（测试里用 Go 的 `EncodeBatch` 生成字节，写进 harness 的假 `fetch`）。
- Produces（页面全局，仅供核心与 runtime-js 使用，名字带下划线）：
  - `window.__tango._open({gen, tok, path})` —— 核心经 Eval 调用，启动轮询循环。
  - `window.__tango._recvSeq(gen, items)` —— Eval 兜底入口；`items` 为 `[[seq, kind, data], ...]`，kind 0 的 data 为字符串，kind 1 为 base64 字符串，kind 2 为栅栏编号。
  - `window.__tango._release(gen, barrierId)` —— 核心执行完 `Eval` 脚本后调用，放行栅栏。
  - `window.__tango._onPacket(fn)` —— runtime-js 订阅字节包（`Uint8Array`），返回取消函数；订阅前到达的包按序缓存。
  - 发往 Go 的内部消息（经 `__tango.post`，前缀 `"\x00tango-int:down:"` + JSON）：`{"op":"poll","gen":n}`（第一次轮询发出前，告知已开始，便于核心计时）、`{"op":"fail","gen":n,"acked":m}`、`{"op":"barrier","gen":n,"id":k}`（交付到栅栏）。
- 行为：只按 `expected` 序号交付，缺号缓存；交付 kind 0 → 现有 `onMessage` 订阅者（保持 `coreShim` 的“无订阅者时缓存”语义），kind 1 → `_onPacket` 订阅者，kind 2 → 发 `barrier` 消息并暂停交付直到 `_release`。轮询失败（网络错误、状态非 200 且非 410、解码失败）→ 发 `fail`，停止轮询。`410` → 静默停止（新世代会再 `_open`）。
