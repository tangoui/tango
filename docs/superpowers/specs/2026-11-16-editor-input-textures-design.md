# Warm editor input texture churn

Base7454931. The user delegates implementation choices and asks for further optimization without UI/features/pixel changes. Reuse the existing isolated editor-performance worktree; standing authorization covers clean local-main delivery and safe app updates, never discarding unsaved edits or pushing remote.

Warm-only1000-key input profile (after setup/full highlight/navigation) shows1414 image uploads,797 exact-size frame-local opportunities, and190ms of900ms sampled in applyImages/newTexture. A second trace finds1404 replaced strip images and zero byte-identical replacements. Variable strip widths explain residual allocation; these counts are workload observations, not latency promises.

Approaches: padding source strips would change filtering/edge behavior; physical oversized textures would require shader/protocol changes. Choose a tiny exact-size spare pool in Metal, leaving images, commands and shaders unchanged. This is a new scope beyond the prior frame-local-only design. Cost: at most1 MiB nominal RGBA texel bytes plus native object/driver overhead retained across frames; the old8 MiB temporary handoff cap remains separate. The source images/renderer caches are still retired promptly.

Keep at most16 unused RGBA8 ShaderRead textures, nominal bytes<=1<<20. Only textures detached after prior GPU submissions complete enter the pool. Claim same-frame candidates first, then exact-size spares, fully overwrite before current draws. Use FIFO eviction (oldest put first), age out after120 subsequent applyImages calls, and discard all spares on a frame with no image uploads. Idle caret redraw therefore releases spares; with no further frames, at most the cap remains. Release on Close, native synchronous/GPU failures and invalid applyImages returns. Bound all return paths; no active IDs may alias spares or each other.

Add optional device TrimImages() invoked by gpu.Renderer.Trim: immediately drop spares and inhibit refilling them for the next applyImages, while allowing existing frame-local handoff for necessary images. No new public UI API, no change to other devices. Trim uses the device mutex and documented native-thread/autorelease setup; it does not wait for GPU because spare textures were detached only after earlier work completed.
