# macOS 编辑器尖峰与真实 GUI 自动化验收设计

日期：2026-11-16。用户选择方案 C：可见窗口的屏幕采集作为 Tango/Monaco 公平对照，Tango 呈现反馈仅辅助归因；中文输入法也自动化，Windows 明确不在本轮范围。

## 1. 意图与现状

目标是回答“真实窗口里的输入、滚动和多光标是否出现可见迟滞，以及真实拼音组字是否正确”，不是继续堆离屏样本或把测试变绿当产品修复。

设计起点为 origin/main `137bb26`。已有 Q 的完整 token 缓存复用、F 的真实 GPU Wait、P retained-copy 和 `TANGO_FRAME_TRACE`。M1 相对退化/默认显示成本已完成统计验收，不重跑这些大矩阵。`dbb1d0e` 已把多光标测试在 Darwin/Linux 上恢复为逐帧原门槛、用线程 CPU 时间排除非本线程运行时间；这一变化不证明真实 GUI 没有迟滞。本轮保留 CPU 与墙钟两种指标。

已核实本机：macOS 26.6、Apple Silicon、本地 Xcode/Swift/ScreenCaptureKit、本地 Edge 与 Monaco 0.56 资源可用；屏幕采集及辅助功能预检均为允许，系统已启用 ABC 和简体拼音。执行时必须再次核对，预检不是今后所有二进制都获授权的保证。主 checkout 由其他会话使用且存在合并中的文件，完全不动；在独立工作区工作。

## 2. 方案比较与选择

- A：仅用屏幕采集。两个引擎使用同一个采样器和真实输入，公平、不依赖浏览器内部事件链，但慢帧归因弱。
- B：仅加 Metal drawable presented handler。Tango 能得到更精确的平台反馈，但不能代表 Monaco，更不能拿它对比浏览器主线程耗时。
- **C（用户已选）**：A 为主要比较，B 为 Tango 诊断，配真实 IME 测试。成本是一个小型 macOS 测量工具及 opt-in 的 Metal 呈现诊断通路；没有证据指向产品热点时不改编辑器算法。

## 3. 测量边界（不可混用）

分别输出以下观测，不把任何一项称为光子延迟：

1. **OS 合成输入投递→WindowServer 画面首次可辨识完成**：同一个原生 Swift 工具用 CGEvent 投递合成按键/滚轮，走原生应用的输入处理链；不是物理键盘/鼠标测量，不包含硬件输入延迟。用 ScreenCaptureKit 采集实际显示器上的目标区域。主时间戳严格使用 `SCStreamFrameInfoDisplayTime`（SDK定义为WindowServer显示该帧的mach absolute time），通过 `mach_timebase_info` 转为纳秒；输入投递点用同一 `mach_absolute_time` 时钟包围CGEventPost，保存前后两个时间。PTS与回调到达时间只诊断，不静默替换displayTime。每个事件保留原始投递区间、最后有效未变帧时间和第一张已匹配预期正文的帧时间，据此给出保守响应区间；displayTime缺失、时间基准不能验证或帧时间早于投递时不强算延迟。
2. **Tango 的 Metal 呈现反馈**：`MTLDrawable.addPresentedHandler` / `presentedTime` / `drawableID`。这是平台报告的呈现时间，不是物理扫描完成；零时间、跳过和未回调均单独记录。GPU command-buffer completed 不等于 drawable 已呈现。
3. **主线程/渲染/GPU 诊断**：复用现有帧 trace 与线程 CPU 测量，用于解释慢帧，不能替代第一项，也不能将不同样本集合的分位数直接相减。

60 Hz 的采集无法分辨所有亚帧差异。不得用插值、取中点或以回调计数充当独立画面帧来宣称 p95≤16ms。区间跨过原门槛或两边差距小于采集精度时标为未判定。保留原规格目标，不另造更宽的通过线。该工具回答新增的“OS输入→合成画面响应”问题；它不与原离屏event→GPU-complete的16ms门槛混判，也不直接取代Monaco内部GPU-complete门槛。报告两边统一SCK口径的观测差异，但本轮不承诺能凭60Hz采集关闭所有历史未证项。

## 4. 原生采集与输入工具

新增本地工具目录 `tools/editor-gui-bench/`：Swift 负责 CGEvent、ScreenCaptureKit、输入源选择/恢复和单调时间；Node 可复用现有本地 Monaco 服务与 CDP 只作启动/状态配置；Go 原生夹具负责创建真实 Tango UI 窗口及输出结果。构建用本机工具链，不新增 Go/npm 依赖、不下载浏览器、不访问远程服务。

- 选择目标 PID/windowID/displayID，要求窗口前台、未遮挡、位于指定显示器。采集实际显示器的测试窗口内容 ROI，不用后台单窗抓图冒充合成显示结果。禁止 capture-all-desktop 落盘；只保存测试 ROI 和人工合成 fixture。
- 试运行先核验逻辑/设备尺寸、显示器刷新率、可见区域、内容scale、时间基准换算及前台PID。逐事件保存激活窗口和焦点证据；CGEvent通过系统事件入口投递，不使用直发内部编辑事件。窗口移动、遮挡、锁屏、displayTime倒退/缺失、buffer空白/挂起须中断本轮并记录。
- `SCFrameStatusComplete` 才能提供新画面的内容；Idle表示画面未变，不等于采集丢帧，不能按两次Complete间距直接计算掉帧。先用单独的、与测试窗口同显示器的校准动画验证采集连续性与帧状态；校准动画不与正式性能采样同时运行。显示器60Hz、采集回调60次和正文更新60次是三个不同指标，必须分开报告。仅靠Complete计数不能证明采集未丢样。
- 只启动/关闭本轮自己创建的 Tango/Edge 进程与临时 profile，不退出用户现有程序；不通过修改权限或关闭系统保护让测试通过。
- 对连续输入使用唯一序列和稀疏节拍，单次完成后再投递下一次，避免并发归因歧义；连续滚动另计整体进度、重复画面间隙和最终到达位置，不伪造每个滚轮事件的一对一上屏延迟。
- 第一帧“有差异”不等于目标完成。输入必须识别正文 ROI 内预期追加字符对应的模式/模板；滚动识别行号/正文变化及程序导出的视口结果。多光标单列“主光标首次更新”和“全部可见光标位置均更新”两项，后者才是可见完成点；屏外位置用最终模型/选区核对，不声称测到了其显示延迟。光标闪烁、候选框、状态栏变化不能单独算正文更新成功。
- 图像比对先在内存做校准与模板匹配，必要时输出匹配置信度；低置信、丢帧和输入未接收单列，不能从耗时分布中静默删掉。报告必须含全部已投递事件总数、成功识别数、缺失数、超时数。若无法排除目标负载导致采集丢样，该轮不能以剩余样本支持 PASS；缺失输入按未观察到完成/右删失记录，单列超时下界及其比例。只有采集覆盖与识别均足够支持所报统计量时才判定，其他情况保持未证。
- 默认保存时间戳、样本ID、ROI哈希/识别结果以及少量前后关键帧，不压缩整段视频来量延迟；若采集自身丢样，先减小分析ROI/工作量并保留1920×1080@2x目标窗口，不能降低目标渲染工作量。
- 偏离（2026-11-17，用户确认）：测试显示器逻辑分辨率 1920×1080，菜单栏 30pt，Edge app 标题栏 32pt，可见正文最大只有 1920×944；1080 高的 Tango 窗口会超出屏幕，并比 Monaco 多渲染约 14% 的行。两边统一用 1920×944@2x 正文，减少的工作量对两边相同。

## 5. 对齐夹具与场景

### 5.1 Tango / Monaco

Tango 使用独立 GUI 验收夹具，直接调用现有 `editor.View`/`uihost.Open`，默认产品渲染路径；强制 Metal 并记录是否 fallback。Monaco 使用真实可见 Edge 窗口、正常 vsync，不开 headless 或解除帧率限制；复用本机 0.56 发行包。两边使用同一生成文件校验和、主题、正文可见尺寸、font size、line height、scale、输入序列及滚轮参数；明确记录不可消除的字体度量/大文件默认降级差异。

夹具允许本地控制通路预设光标/视口/选区和读取文本摘要/版本，但计时期间必须经过OS原生输入链，不用 `State.Insert`/CDP insertText 冒充按键。控制通路限本轮进程的本地私有通道；状态采样采用有界内存记录，计时关键路径不做同步HTTP/文件IO，不改变产品输入行为。

正文匹配先用每个引擎各自、固定字体/缩放的稳定画面模板校准追加ASCII字符的位置与像素签名；正式输入采用已校准的确定序列，逐次核对预期模型版本和可见正文像素。不能以模型更新或状态栏更新单独结束计时。pilot若无法可靠匹配正文，停止该项，不直接扩成任意OCR或另画一个更快的确认标记绕过正文。

正式对比时Tango的新增present诊断关闭，避免只有Tango承担block回调/日志开销。pilot中允许各一次同负载的诊断关/开检查，单独记录观测开销；仅对复现异常的Tango场景再开诊断跑一次短归因（上限30个事件）。归因结果不拼入正式对比。主程序两边的前后台高亮状态与预热方式固定、记录并复用，不能一边静止一边忙着初始加载。

### 5.2 固定运行预算（我的实施默认值）

先各跑一个短 pilot：10 次稀疏输入、30 次滚动；用于验证权限、帧识别、host clock 和采集开销，不做 PASS 声明。正式运行先固定为 **3 对 AB/BA 交替**，每引擎每对：

- 1M 行文件，中段输入100次真实按键；记录输入→合成画面响应分布/区间、最后文本与光标正确性。
- 1M 行连续滚动240个事件：记录可辨识进度、最长重复画面间隔、截图/视口与滚轮方向一致性。rAF/SCK回调吞吐不叫实际显示fps。
- 6000行/30光标与100000行/100光标：固定括号匹配场景及30次输入/导航，测墙钟可见响应；同时保留CPU工作、目标PID CPU、host负载和present诊断。不发散到其他引擎/框架。

执行期间保持单实例 OUT 锁、机器资源明确交接、负载<6、屏幕解锁；前后环境不满足的轮次单列，无限等待/追加轮数不允许。每组最多2次环境失败重试，达到上限输出阻塞原因。3对结果只能给样本内结论和不确定性，不把小样本差异说成普遍结论；不足以判定时先报告，不擅自恢复20/40轮矩阵。产品热点最多进行一次有回归测试与profile依据的定点修复，再做一次同样3对的修复后测量；仍失败/无法归因则交付证据与遗留，不再追加产品优化轮。测量器pilot至多两次适配修正，仍不能可靠关联帧则停止正式采样。

### 5.3 多光标尖峰处理

先检查最新测试与现有线程CPU诊断是否一致，验证CPU门槛保持逐帧、墙钟尖峰仍可见。若真实窗口也能复现迟滞：以同一事件/帧ID关联输入、处理、render、drawable与采集帧，区分产品同步长任务、Go/OS调度及采集缺帧。只有能用稳定工作量/像素/行为回归测试证明的产品热点才按TDD做最小修复；不能通过改中位数、提高倍率或改统计量消除真实迟滞。无法归因的调度/硬件问题保留未证，不承诺软件能消除OS所有抢占。

## 6. Tango 呈现诊断通路

在现有 Metal/presenter 与 uihost 帧 trace 旁新增显式 opt-in 呈现记录（保持默认关闭）：

- 每次 present 保存独立递增present序号、render帧号、surface/session世代、drawableID、host提交时间；回调捕获同一身份，避免resize、重复present和窗口重建错配。
- Objective-C block 与 Go 桥接生命周期必须明确。异步回调仅写入有界队列，不持 Device mutex、不直接调用现有 mutex-held `SetTimeline` 回调，不做IO/图像分析、不阻塞main thread。
- 队列满、回调晚到/乱序、presentedTime=0、Close后到达均统计；不丢弃失败样本后假装零丢帧。Close不无限等待呈现；残留block/Go句柄有可验证的释放路径。使用项目现有 purego/objc.NewBlock，不新增桥接依赖；block捕获独立、与Device生命周期解耦的有界记录器，原生API持有其复制后的引用，本地引用按API所有权规则释放。回调不捕获已关闭的Device/Renderer或循环持有drawable。只有完成验证的呈现事件进入统计，零时间不伪造为回调到达时间。
- 只导出诊断字段，不改变in-flight数量、vsync、渲染算法和product默认调度。不开诊断时不注册回调/不额外分配。
- 验证Off、异步回调重排、关闭/resize、缺失反馈和queue overflow，及现有Metal像素/生命周期/conformance测试。

## 7. 中文拼音 IME 自动化

从当前输入源读取并保存状态，测试结束/异常尽力恢复输入源与焦点，不改系统默认偏好。选择已启用的简体拼音，通过真实KeyDown/KeyUp逐键输入拼音，必须观察到marked-text/Composition start/update，再选择候选提交；禁止用剪贴板、Unicode CGEvent或直接发TextInput冒充IME。

案例：单光标组字/提交；Escape取消；组字中Backspace；候选选择；左右移动后再次组字；提交undo/redo；3光标时只在主光标预览、提交到全部光标；失焦取消。每个案例在运行前确定精确文本/选区/撤销预期：例如拼音nihao→预定测试词“你好”，取消后保持初始文本，undo恢复原文、redo恢复提交。不得先观察任意中文结果再把它当预期。

IME轨迹从原生 `setMarkedText` / `insertText` 所产生的真实Composition/TextInput事件观察，以仅夹具/开发诊断开启的被动observer记录，不能只订阅ModelChange（组字尚未提交时Model应不变）；禁止直接调用native setMarkedText模拟系统输入法。observer不改事件、不吞按键、不读全局用户输入。组字期间有Composition更新而buffer不变、提交后精确结果/undo符合预期，才可判功能通过。候选窗不可观察或系统词频使预定词不可确定选择时，对该案例标阻塞，不能只断言“出现中文”。已选测试词可能进入系统输入法的自学习，退出仅恢复输入源和本轮持有的焦点，不承诺还原输入法学习数据。

不导出输入法用户词典，默认不落盘完整候选窗、不记录候选列表；只记录本次明确选择的合成测试字符串。需要验证候选窗位置时，仅保存边框/锚点位置，所有候选正文在内存中遮蔽；组字下划线截图仅保存夹具正文ROI。若无法在落盘前可靠遮蔽，则只记候选窗存在/位置并将视觉内容检查标为未证，不要求用户提供额外隐私授权。

## 8. 测试、报告与边界

- 模拟采集样本的纯逻辑测试：clock转换/区间、frame状态、重复/缺帧、ROI与scale变动、cursor-only变化不能命中正文、错误window/输入PID、超时统计、唯一事件匹配。
- GUI与IME只使用合成内容；截图及时间线留在ignored证据目录，不上传外部服务。
- 报告分“采集画面响应”“Metal平台呈现反馈”“CPU/GPU诊断”“IME功能”“未判定/阻塞”。每项写清版本、命令、样本数、无效样本及原因和退出码；失败/未证必须保留。
- 稀疏输入以每个已投递事件的延迟上下界计算 p95 的上下界，采用最近秩 `ceil(0.95*N)`，超时/未识别事件不能从N中删掉，其上界为未知/无穷；采集失效的一轮不判PASS。三对结果逐对呈现，不把帧/按键当作相互独立的重复试验去计算过窄的总体置信区间，不凭三对声称达到既有≤10%的统计证明。两引擎响应区间/采集精度重叠时只报告不能区分。
- 本轮将验收拆为“功能正确”“观测有效”“是否满足现有目标”三列；功能正确且观测有效不自动等于所有性能目标通过。已存在的离屏统计PASS不重跑，也不因新指标而覆盖。
- 在所有可做自动化完成后更新 `docs/specs/code-editor-m2-report.md` 的对应遗留项；不把Windows、物理扫描/光子、Monaco内部硬件身份链自动改为通过。
- 本轮先在独立worktree实现与验证，不自动合并或推送，集成时再按用户指令执行。
