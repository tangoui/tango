# Editor Metal image texture reuse

Continue from e260df5 in the existing clean editor-performance worktree. User delegates implementation and has standing authorization for clean local-main integration and safe app updates. Preserve current UI, all editor features, immutable CPU image/list contracts and all GPU backend behavior.

Current profile points to Metal Device.applyImages (0.31s cumulative of1.33s sampled), including native texture creation/release. Execute waits for previous work before applyImages. Reuse exact-size RGBA8 ShaderRead image textures which this frame already frees, and overwrite them completely before the current frame draws. Also reuse an already held same-ID texture on a complete same-size reupload. Leave image IDs, upload order, cache limits, failure policy and pixel content unchanged.

Alternatives: a cross-frame pool has added idle-memory/Trim/failure complexity; a mutable image/texture-update protocol spans all backends and public lifetimes. Choose a frame-local handoff: at most32 freed textures and8MiB, no GPU resources retained across calls, unmatched candidates released on every return including errors. This can briefly retain up to8MiB during applyImages but adds no cross-frame GPU residency. Size metadata follows live image IDs only. Oversized/no-upload frees release immediately.

Prove native object reuse while retaining the old object in the test (prevents allocator address recycling false positives), verify exact pixels after reuse, mismatched sizes, replacement, duplicate frees, multiple equal-size images, invalid frames and Close. Run Metal conformance/damage/layer/golden tests, root/editor regressions, race/vet, and real before/after full/partial editor benchmarks. Distinguish CPU submit wall time, process CPU and GPU wait; require a measured native allocation reduction and report noisy frame timings honestly. No absolute-latency/FPS claims.

Measured extension: native-only reuse reduces isolated churn, but real editor opportunity is limited while private replaced minimap images remain in the renderer cache for up to300 frames. Add Context.InvalidateImage as an additive cache-retirement helper on the UI goroutine before rendering, forwarding existing CPU/GPU invalidation capability through the native fallback wrapper. Retire only discarded private minimap strip image values (replacement, scrolling out, glyph/sampling changes, disabling). Never mutate image pixels or change the rendering protocol. Existing recorded lists can still redraw a retired immutable value and it will be reuploaded normally. No implicit Damage for in-place edits; document caller responsibility. Unknown renderers safely ignore the optional cache hint. Update API listing, integration tests and CPU/GPU/fallback checks.
