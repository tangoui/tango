# Tango 全模块性能优化

目标：在保持 API、输出、并发和交互语义的前提下，对所有模块建立可复现性能记录，持续消除已定位热点。原有同场景 MyGo 领先 10% 的要求保留；没有等价实现的场景记录自身 A/B，不能借个别 Go 分词场景宣称整体领先。

基线：40ed885（2026-11-16）；当前 macOS/arm64 共 171 个包，20 个包有 115 个 benchmark 顶层函数。第一轮已顺序跑 14 个包 81 个子场景，原始证据在 /Users/admin/min/outputs/tango-perf-audit-20261116。

方案：先覆盖审计，再按 profile 的成本和使用频率优化共享路径；不用全项目重写或只追逐单一 benchmark。每批单独运行正确性、分配回归及同机多次基准，报告收益和未覆盖项。

第一批：图布局临时工作区复用；图表下采样临时索引；大文件换行归一化；复核之前的 Go lexer 快路径是否与通用实现保持一致。每项必须先定位、再建立失败回归、再最小修改。

后续批：IPC/绑定/资源/服务的测量缺口，文本 shaping 与 UI 调度，渲染、宿主、CLI、国际化和平台接口。macOS 本机性能与 Windows/Linux/移动设备数据分开；编译通过不能代替性能验收。

验收：顺序测量、新鲜进程、环境和负载可追溯；持续运行和冷启动分列。不得改输入规模、跳过绘制/高亮或忽略输出差异以获得速度。保留全量测试失败的名称与日志；显式标明未测、未优化、无收益和目标未达标。

“极致”用边际收益与成本证明，不能承诺数学意义的全局最优；每批完成不代表全项目完成。
