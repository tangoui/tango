# Tango 编辑器核心性能超过 MyGo 10% 设计

日期：2026-11-15

## 意图

在同一台 Apple M4、同一 Go 版本和同一输入数据上，优化 Tango 编辑器核心路径，使每个选定核心 benchmark 的耗时不高于 MyGo 的 90%。当前缓冲区编辑已经达标；主要短板是 Monarch 分词路径。

## 目标

- 缓冲区编辑、快照/索引、语法分词分别测量，不用综合平均数掩盖单项回归。
- 对每项选定 benchmark，Tango median `ns/op <= MyGo median * 0.90`；吞吐指标则 `>= MyGo * 1.10`。
- 保持 token 结果、跨行状态、UTF-16 列、超时降级和编辑器公开 API 不变。
- 每个优化先有可复现 benchmark 或正确性回归，再修改实现。

## 非目标

- 不复制 MyGo 代码或语法数据。
- 不改变 benchmark 输入来制造优势。
- 不修改 GPU、平台宿主或 UI 框架来掩盖编辑器核心路径问题。
- 如果某项需要重写整个语言系统才能达到目标，保留证据并明确标记未达标，不降低门槛。

## 方案

1. **核心路径优化（采用）**：先 profile `ui/editor/monarch`、`ui/editor/highlight` 和 `ui/editor/buffer`，消除重复分配、重复正则匹配和不必要的状态构造；保持语义测试全绿。
2. **专用 Go 快路径**：为 Go 语言增加独立手写 lexer。潜在收益大，但会扩大语法覆盖和维护范围，仅在方案 1 证明通用 Monarch 路径无法达到目标时考虑。
3. **端到端渲染优化**：调整 GPU/窗口帧路径。该方案不属于核心算法口径，暂不采用。

## 验收

- 基线、优化后和 MyGo 均使用三轮以上同机 benchmark，报告 median、范围和分配数。
- `go test ./ui/editor/... -count=1` 通过。
- 分词 fixture、跨行状态、长行降级和并发测试通过。
- 若任一选定指标仍高于 MyGo 的 90%，报告中明确列出未达标项和 profile 证据。
