# macOS 独立 UI 线程分阶段合入

## 目标

先把每窗口独立 UI 线程的实现合入 `main`，但不让普通 macOS `uihost.Open` 窗口走尚未通过性能验收的新路径。Task 11 保持未完成；合入基础实现不等于通过验收，也不改变任何门槛。

## 方案比较

- **等验收全部通过再合入并默认开启。** 对外只有一次变化，但长期分支需要反复同步 `main`，也推迟了后续优化基于同一代码开展。
- **先合实现、默认关闭，后续单独开启默认（已选）。** 保留实现与测试覆盖，普通窗口继续按主线程模式运行；将来单独提交开启默认，便于审查与回滚。

## 第一阶段

- 普通 `uihost.Open` 不再通过 `CanvasThreadedSink.WantsUIThread` 请求独立线程。保留平台能力、线程实现和现有的内部门控测试入口；不新增对外配置、环境变量或 API 开关。`Attach`、`tan dev` 和其他平台的线程模型保持原样。
- 保留已经迁移到 `Runner.Post` 的示例和现有线程安全修复。公开包注释、站点、CHANGELOG 和迁移文档须区分现在默认的主线程模式与内部测试路径；不把迁移写成已生效的强制要求。开发版线程检查仍只适用于实际绑定线程的 Runner。
- 对齐最新 `origin/main` 后，验证普通窗口不请求线程化画布，内部门控测试仍能覆盖新路径；检查共享改动未破坏默认路径。跑受影响的功能及竞态回归、全仓短测试、三平台 vet、格式和 API 清单检查，按项目规则补齐合并前审查。真机功能验证如需占用前台，另行确认时段；不把旧构建的结果当成此次合入候选的结果。
- 保留独立工作区、台账和原始测量数据。验收或最终审查发现阻塞项则先处理，不能借默认关闭掩盖共享路径上的缺陷。

## 第二阶段

在同一最新基线完成 Task 11：列表 CPU 和网格长跑、切前台对照、编辑器打字延迟、拖动改尺寸、中文输入法、VoiceOver 与 WebView 对齐；已有结果仅在候选未影响对应路径时复用。保留全部样本，沿用 P99 1 ms、慢帧比例 0.3 个百分点、内存与 CPU 5% 的原门槛。通过后才另行提交并审查默认开启，同时更新公开文档；这一步不包含在本次合入范围内。
