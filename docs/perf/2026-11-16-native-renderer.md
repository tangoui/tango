# macOS 原生渲染：实现、初测与验收边界

后续的解锁复测、文字图层优化和一分钟结果见 [第二轮报告](2026-11-16-native-renderer-round2.md)。
本文保留第一轮历史数据与当时的验收边界。

已实现 macOS Apple Silicon 的保留式 Core Animation / CoreText 渲染器。
它复用未变化的内容图层，整像素移动不重新绘制文字；圆角、边框、阴影、
路径、渐变和图片使用可复用的有界 CPU 参考位图。复杂裁剪、透明度组、
变换、背景模糊和超过 64 MiB 的预计原生位图完整回退，不省略绘制命令。
组件 API、主题、文字排版、输入法和可访问性接口保持原有语义。

## 为什么 NSGo 的内存更低

本轮核对的 NSGo 主分支是 `7eba948c85cb125cd181a2a736ec018090d3dfd6`。
其 `internal/platform/macos/content.go` 为文字/画布使用独立 CALayer，
只重绘可见且内容或尺寸变化的图层，避免 AppKit 为每个 drawRect 视图记录、
重放完整绘制列表。Tango 原先的整窗 Metal 路径承担设备、流水线、纹理、
字形图集和 drawable 的固定驻留成本。只改 Go 节点分配或 Metal shader，
不能消除这些原生图形资源成本。

Tango 新增同类的保留式内容路径，同时继续支持现有跨平台显示列表和 Metal。
这并不意味着整个框架、每一种 UI 和每一种硬件的性能已经等同。

## 当前启用范围

- macOS/arm64 普通自绘窗口，面积不超过 100,000 逻辑像素：默认原生。
- 更大窗口、Intel macOS 和其他平台：保留 GPU 优先及其 CPU 回退。
- `TANGO_RENDERER=native`：支持的平台和窗口强制原生，可比较大窗口低内存路径；不自动升级。
- `cpu`、`gpu`、`auto` 和调用方自选 Renderer 保持原语义。
- 默认原生的窗口，连续六帧工作超过 8 ms 或连续六帧整窗软件回退，且帧间
  空闲时间不超过 100 ms，尝试一次 Metal；失败立即呈现 CPU，不反复重试。
- 透明/材质窗口和 WebView 附加画布保留原路径。

较大窗口尚未通过原生默认路径的持续 CPU 和尾部帧间隔验收，因此没有扩大默认范围。
原生文字抗锯齿遵循 CoreGraphics；CPU/Metal 的既有像素测试和容差未放宽。

## 第一版三轮初测，不代表最终实现的性能

环境为 Apple M4 / 16 GiB / macOS 26.6，Go 1.27.3，CGO=0，
发布编译 `-trimpath -ldflags '-s -w'`。Tango 源码固定在 `457fe47`，
包含 `c1cda21` 的有界异步 Metal 改进；原生/GPU 使用相同 Tango 应用代码与构建参数。
每场景三轮交错顺序，先稳定 3 秒、再测 10 秒；不强制 GC、不在计时中截图。
CPU 校准的单线程忙循环为 98.26%，Mach timebase 为 125/3。

物理 footprint，十进制 MB，中位数：

| 场景 | NSGo | Tango Metal | Tango 原生 |
| --- | ---: | ---: | ---: |
| 静态计数器 | 25.5 | 53.3 | 42.2 |
| 行情表 | 47.1 | 158.8 | 63.4 |
| 滚动列表 | 42.4 | 142.0 | 45.1 |

应用 CPU，单核百分比：

| 场景 | NSGo | Tango Metal | Tango 原生 |
| --- | ---: | ---: | ---: |
| 静态计数器 | 0.0 | 0.3 | 0.9 |
| 行情表 | 18.8 | 18.7 | 24.0 |
| 滚动列表 | 12.2 | 9.7 | 12.6 |

回调间隔 P99，毫秒；这是应用回调，不是实际呈现 FPS：

| 场景 | NSGo | Tango Metal | Tango 原生 |
| --- | ---: | ---: | ---: |
| 行情表 | 26.15 | 22.80 | 28.28 |
| 滚动列表 | 28.71 | 17.76 | 32.89 |

该版原生行情/列表内存分别减少约 60% / 68%，列表内存已接近 NSGo；
但应用 CPU 和尾部间隔仍有代价，不能据此宣称全面更快。
计数器接近空闲时的不足 1 个 CPU 百分点差异，不能作为稳定功耗结论。

本轮机器存在其他应用与测试的并发负载：57 次后台采样中 53 次看到其他
`.test` 进程，最高合计约 200% 单核 CPU；WindowServer 的静息值约 32–42%。
行情/列表的 WindowServer 增量中位数为 NSGo 0.6/0.0、Metal 0.4/0.2、
原生 1.8/1.0 个百分点。较高且变化的背景值使这些增量和尾部延迟只能作为
带负载初测，必须在较低负载下复核。不能用应用进程 footprint 代表全系统图形内存。

## 初测后的修正与未完成的测量

CPU profile 指向原生事务提交和后续独立文字绘制。已将变更文字的绘制
合入 Render 的同一显式事务，并把事务提交包含进工作时间统计；
新增测试先复现旧实现没有完成文字绘制，再验证修正。
同时修复负尺寸实心矩形误绘、渐变绝对抖动相位、棋盘格默认颜色缓存失效。

修正后的 GPU/原生诊断出现接近零 CPU，检查发现系统已经锁屏、没有
`bench ready`，两个后端都未获得首帧；该组数据无效，未用于任何节省结论。
已请求解锁。修正后的三轮复测和一分钟滚动尚未完成；本报告不填入推测值，
也不把初测结果冒充最终版本的测量。

## 实现决策与代价

1. 圆角/边框等采用有界 CPU 参考位图，保证现有覆盖率；代价是首次栅格和图片内存。
2. 自定义/彩色字体不支持原生桥时，只回退其文字位图；代价是该部分的软件绘制。
3. 64 MiB 位图预算采用保守面积估计，超额完整回退；可能对共享图片提前选择 CPU。
4. 自动升级的间隔按前一帧完成到本帧开始的空闲时间计算；避免慢帧自我重置，
   但慢事件流也可能升级。
5. 调度冒烟测试复用像素未变化的不可变图片，避免把调度检查变成整窗图片重采样；
   每帧新建大图片仍属于原生路径需要升级/显式 GPU 的工作量。
6. 大窗口保留 GPU 默认，待解锁后的新测量再扩大；代价是尚未获得默认的大窗口内存节省。
7. 独立审查聚焦新增原生代码，main 合入的其他改进保留并参与完整测试；仍可能存在其自身问题。
8. 审查期间禁止跑测试以免污染计时，执行者负责后续验证；其他硬件只做交叉构建覆盖。
