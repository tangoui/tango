# 2026-11-16：完整 Tango 的启动字体内存

最终完整计数器的三次进程内存观测为28.39–29.12 MB，中位数28.77 MB；同轮固定版本 NSGo 为25.36 MB，差约3.41 MB。主机有其他编译/测试负载，因此这是该环境下的内存观测，**不是空闲环境基准，也不构成 CPU、启动耗时或 P99 改善结论**。

## 来源与测量

增量基线是 `116b9e63c415d0e2ec74b2f029208d4b980ee3e2`。该 main 已包含只读字体共享、按 Face/坐标缓存整形器，以及超过64次调用才特化 HVAR 的优化。本提交保留这些实现和回归测试，继续消除冷标签的 GDEF 特化成本及字体文件的中间副本。

- macOS/arm64，Go1.27.3，`CGO_ENABLED=0 GOWORK=off`，`-buildvcs=false -trimpath -ldflags '-s -w'`；项目保留各自锁定依赖版本。
- Tango 使用同一份完整组件计数器源码、360×260窗口、Ant Design主题和原生后端。没有换成 macoslite、裁掉组件或转移到辅助进程。
- NSGo 固定为 `2449cc530e72bec3c0f1329890cf744ef1e563b6`；本表不代表后续版本。
- 顺序按“基线、NSGo、修改后”交替三轮，第二轮反序。等待真实第二帧 `bench ready` 后采样约15秒，每轮取末五次 footprint 的中位数，表中再取三轮中位数。MB为十进制，数据来自 `proc_pid_rusage` 的物理 footprint。
- 屏幕保持解锁；正式内存采样无强制GC、截图、CPU profile或堆profile。提前正常关闭的进程已丢弃，每个有效内存观测均完成真实绘制并存活至采样结束。
- 每秒记录后台编译/测试负载。原始数据的 `valid=false` 表示没有通过空闲环境的**计时**资格筛选；这些 CPU/首帧时间不用于发布性能结论。内存表保留三次完整观测及范围，不把波动较低误作置信区间或通用框架排名。

## 最终实现

1. CoreText resource只保存 sfnt 表目录，go-text直接把所需字体表读入自身解析缓冲区，去掉“复制所有表→拼接字体→解析再复制”的中间文件。resource自己保留原始CTFont，覆盖 raster 后续替换变体字体、并发读取及失败释放路径。
2. HVAR特化复用现有表缓冲区作为虚拟sfnt输入，继续走完整的公共字体解析器，去掉整份字体的拼接和校验副本。
3. 冷字体先使用原始度量；沿用 main 的第65次整形调用才特化策略，把原先仍然提前执行的GDEF特化也延后。坐标/ppem变化重置实例计数；计数饱和；稳定热实例避免每次回写缓存。缓存仍最多16项，TrimCaches仍丢弃它们。64次是摊销启发式，不是已证明的最优拐点。

系统可变字体仍共享一份只读 `font.Font`；各字重有独立 `font.Face` 的坐标、ppem和字形缓存，运行时整形器按Face/实例状态缓存。main已有的快路径和共享字体回归保持不变。组件API、主题外观、字体引擎选择、回退、换行和测试精度没有改变。

较多或持续变化的文字会按需支付特化成本，因此28.77 MB不是所有界面或长时间运行后的统一上限。

## 分配与外观证据

独立诊断构建中，`f7bb842` 到最终实现的启动累计Go分配 `TotalAlloc` 为28.221→7.840 MB。它包含启动临时分配，是累计优化的诊断观测，不等于常驻堆、进程footprint或本提交相对最新main的单独贡献。诊断含截图和heap profile，不能替代上表。

旧实现回归测试可复现字体数据源每次约3.27 MB Go分配、度量特化每次约5.86 MB分配，以及单个静态数字也创建额外特化字体。对应目录/缓冲区复用、冷标签及热实例只特化一次的回归均通过。

最终版本与旧计数器的720×520自有图层截图逐像素一致。独立解析字体的 glyph、cluster、offset、advance 对照覆盖字重顺序、斜体和11/16/56字号；既有全字形度量、GDEF增量、CJK/Arabic/emoji和实例状态回归继续有效。新增ppem-only变化验证已特化实例重回原始度量并使用新像素度量。
