## 结果与验收

低负载复测取得五对完整样本：每次新进程、串行、交替顺序，前后 1 分钟负载均低于 6，且 Tango 监测的 `timeouts/op`、`degraded/op` 均为 0。双方固定 Go1.27.3、CGO_ENABLED=0、Darwin arm64；混合语料保持相同的 37,200 字节，双方跨文档复用 token 容量。原始记录见 `final/recheck/matrix-raw.json`，汇总见 `final/recheck/matrix-summary.json`。

| 普通文本 | 50,197 | 50,151 | -0.1% | 基本持平 |

本批混合 HTML 热路径相对旧实现降低 14.2% 耗时；这不是“比 MyGo 快 50%”的结果。MyGo v0.9.0 同语料中位数为 210,144 ns/op，Tango 优化后为 2,965,178 ns/op，约为 MyGo 的 14.1 倍耗时，仍未达到逐场景 `Tango ≤ MyGo × 0.50` 的验收目标。两者语法覆盖、token 格式与 API 能力不同，不能据此宣称功能等价。

分配方面，最终组合的五对混合 HTML 样本每文档分配次数从 16,901 降至 13,430，减少 20.5%；分配字节从 1,311,949 降至 1,151,104，减少 12.3%。这是自身前后分配改善，不能等同于 MyGo 领先。冷编译首片段分配从 39,226 增至 42,464，增加 8.3%，字节从 4,025,887 增至 4,245,162，增加 5.4%。

## 实现与成本

- 分组动作复用每次 `myTokenize` 调用内的容器，首次需要时才分配最多四项的小组存储；超过四项使用动态存储，递归调用保持独立。空行与默认字符复用已有单捕获槽。首次固定数组方案因逃逸增加空行分配而被预算测试否决，失败日志和逃逸分析保留。
- 从 regexp2 对已翻译、已锚定源码的首字符分析提取不可变 ASCII 位图，公共匹配入口提前排除不可能匹配的ASCII首字节。使用与原引擎一致的options和大小写转换；空输入、Unicode首字节、nullable/不支持和超长表达式保留原匹配路径。私有注入时钟/匹配函数的超时测试路径不变。
- Monarch原有字面量前缀过滤区分顶层与嵌套选择；顶层替代分支、可选首字面量、ignoreCase、inline options、注释和非JS分组扩展保守回退。含竖线的额外扫描与regexp2首字符分析均限制在512字节源码内。
- 首字符分析会额外执行一次受限的regexp2 Parse/Write，只保留位图，增加冷编译工作和分配；这是热匹配路径与编译路径之间的成本交换。本轮不宣称冷启动改善。无共享scratch池、grammar简化、预算放宽或MyGo生产实现复制。
