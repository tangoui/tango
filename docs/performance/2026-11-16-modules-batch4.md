# 第四批：通用分词与 MyGo 50% 目标

## 范围和口径

基线 `ebcb400fccb4d04cba23b01f121be0425a231ff9`；在 `perf/all-modules-20261116` 分支继续。用户提出希望比 MyGo 强 50%，本批采用更严格的耗时门槛：Tango 中位数 ns/op ≤ MyGo ×0.50，同时单列吞吐倍数。每项分别验收，不作全项目领先结论。

参考固定为 MyGo v0.9.0。双方 API、Token 结构、语法覆盖和并发能力并不完全相同：这里是相同输入的单线程核心 API 工作负载比较，不是像素输出一致或整个编辑器功能等价的证明。Tango 自身优化前后的语义则必须完全一致。

证据目录：`/Users/admin/min/outputs/tango-perf-batch4-20261116/`。正式比较双方均重编为 Go 1.27.3、CGO_ENABLED=0、Darwin arm64、Apple M4；二进制 buildinfo、SHA256、命令、cwd、负载和输入哈希均存档。

**历史校正：** 检查旧二进制发现，第一批 Tango 实际使用 Go 1.27.2，而 MyGo 使用 1.27.3；此前 61.6% 不能作为同工具链的合格结论。本批不沿用旧比例。原始数据保留，第一批语义修正和自身 A/B 不因此撤销。

## 本批实现

- 编译动作时预计算静态 token 类型及 sanitize 结果；保留对象 token 的动态替换、brackets、cases/group 和空 token 语义。仅预计算最多 256 字节的完整类型，超长标签/postfix 回到原路径，避免编译内存按规则数放大。
- 将每次 myTokenize 的 matchCtx 和单 capture 放在同一个调用帧中；递归嵌入仍有独立帧，没有全局共享缓冲。
- 短 ASCII 行只有真正尝试回溯规则时才转换一次 rune 切片，随后按当前位置截取。Unicode、非法 UTF-8 和长行保持原有路径，匹配、超时和工作上限仍执行。

Go 的专用手写快路径本批未改；主要新收益来自通用 Monarch/高亮共享路径。没有通过省略语言、token 或跨行状态来改善数字。

## 正式测量方法

每项各 5 对，新进程、交替先后顺序，全部 50 次正式测量前后 1 分钟负载均 <6（约 3.57–4.24）。最终有界驱动允许每项最多8对以补失效样本，本轮5对即完成；较早的预备矩阵因代码尚未加入长标签内存保护而单独保留，不混入最终结果。

Go 为同一 38,200 字节语料，HTML 为同一 37,200 字节语料，均重复同一片段 200 次并跨行传递状态。新 warm 场景双方跨文档保留 token 容量；这区别于第一批 Tango 每文档重新创建 token 容量的场景，不能把旧6次分配与新0次直接当作本批收益。

缓冲编辑输入为相同 100,000 行、3,477,780 字节，每进程固定1,000次从中间连续插入字符，各自保留撤销记录；不使用不同自动迭代次数产生的历史长度差异制造优势。两者内部日志保留、锁和快照实现仍有差别，本表不代表这些能力完全等价。

表中的 ns/op 为每轮平均耗时的跨轮中位数，不是事件延迟 p50。`final-paired.json` 保存每次原始记录，`final-summary.json` 为严格成对筛选后的汇总；`input-manifest.json` 逐项核对双方生成输入，`comparison-toolchains.json` 和 buildinfo 记录工具链。

## 正确性与验证

- 失败回归：静态类型203次分配、短ASCII回溯203次、匹配帧4次，分别超过125/125/3预算；优化后通过。超长postfix的编译分配曾为73,783,816字节，超过32 MiB预算；加入大小上界后预算及原样标签输出均通过。日志保留，不抹去中途失败。
- 固定旧/新二进制运行全部内置fixture，加上Go/TS/HTML各2,000组三行生成输入，共24,881条记录；token类型、UTF-16/字节偏移、State和LineInfo逐字节一致，见 `differential-result.json`。
- 新增默认/空类型、字符串字面$、对象替换、cases/group、brackets、grammar替换所有权、Unicode/非法字节和并发回归。既有降级、嵌入、panic、长行及fixture测试保留。
- Go1.27.3最终相关模块普通测试和race均通过（分别10.45、79.94秒），独立静态审查未发现确认问题；之后新增的长标签保护通过失败→通过回归及最终完整验证。
- 首次全项目测试有 `TestActiveGuideFirstCallFast` 单次12.7505ms超过5ms，完整日志 `full-tests.txt` 保留。未改门限；旧实现和优化实现各单独5次均通过（旧2.09–2.71ms，新1.96–3.29ms）。最终完整Go/CLI测试通过（493.06秒），该门禁在完整复跑中也通过；全项目/CLI vet通过（8.42秒），格式与diff检查通过。见 `checks-final.json`、`full-tests-final.txt`、`full-vet-final.txt`，源码与测量二进制哈希均核对一致。
