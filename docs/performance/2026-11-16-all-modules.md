## 修改与正确性

- 图布局：精确计算虚拟节点和邻接表容量；单次 Layout 使用局部邻接存储和坐标拟合工作区，避免全局共享可变池。
- 图表：稠密 LTTB 直接使用原始索引；只有遇到 NaN 才创建映射。用旧算法对照 130 种长度、3 种稀疏程度和多个阈值。
- KV：无落盘场景在现有互斥锁内更新，持久化路径继续 copy/write/publish；保留编码失败时状态不变。
- 分词：修复上一轮快路径中 hex/octal、转义、Unicode、文档注释、操作符和自定义 grammar 的偏差；移除不等价的 go/scanner 回退。为通用正则首字符筛选增加 alternation/可选前缀保护。3,000 组生成输入与后续状态对照、所有内置 fixture 和自定义 grammar 回归均纳入测试。

上一轮分词“语义完全不变”的结论证据不足，应撤回。旧领先比例不能沿用。修正后与 MyGo v0.9.0 在同一 38,200 字节 Go 语料上交替各跑 5 轮（每轮 500 ms，新进程，前后负载 <6）：Tango 144,437 ns/op（范围 140,231–149,531），MyGo 375,938 ns/op（374,833–385,133），Tango 耗时低 61.6%。这是固定语料的分词比较，不代表全部语言、端到端编辑器或全模块。Tango 2,145 B/op、6 allocs/op；MyGo 约 41 B/op、报告的均摊 allocs/op 为 0，分配指标仍由 MyGo 占优。原始数据和二进制哈希见 `corrected-lexer-comparison.json`。

## 基准覆盖补齐

新增 IPC 包编解码、反射绑定（普通/Context/变参）、资源 HTTP 响应、语言匹配/消息格式化、内存 KV 和 Shader 前端基准。IPC ParsePacket 只解码元数据，负载切片零复制；其按 payload 计算的 MB/s 不是网络/WebView IPC 吞吐。资源响应基准包括 httptest Recorder 的分配与拷贝。Shader Load 属于构建工具成本，不能算成应用逐帧成本。
